# 三机严格版（A 主控 / B 采集 / C 发包）

## 三机角色

1. A 机（主控）
   - 运行 `app_coin_master`
   - 提供符合服务与采集控制服务

2. B 机（采集）
   - 运行多个 `app_acq_r2s_node`
   - 执行采集 + 单事件转换 + 流式发送

3. C 机（发包）
   - 运行 `app_udp_raw_replayer`
   - 负责真实数据回放或压测流量生成

## 三种场景

1. 正确性测试
   - 路径：`app/experiments/three_machine/correctness/`
   - 目标：回放真实数据并对比结果（可选 md5）

2. 极限性能测试
   - 路径：`app/experiments/three_machine/extreme/`
   - 目标：最大速率发包，验证系统性能上限

3. 稳定性测试
   - 路径：`app/experiments/three_machine/stability/`
   - 目标：中等速率长时间运行，验证稳定性

每个场景均包含：

1. `A_start_master.sh`
2. `B_start_acq.sh`
3. `C_start_sender.sh`

## 占位符模板

模板位于：`app/config/three_machine/templates/`

关键占位符：

1. `__A_MASTER_IP__`
2. `__B_ACQ_IP__`
3. `__C_SENDER_IP__`

脚本会自动渲染模板到：`app/config/three_machine/runtime/`

## 启动前环境变量

三台机器均设置：

```bash
export A_MASTER_IP=<A机IP>
export B_ACQ_IP=<B机IP>
export C_SENDER_IP=<C机IP>
```

## 启动顺序

1. A 机先启动主控脚本。
2. B 机启动采集脚本。
3. C 机最后启动发包脚本。

## 日志与清理

1. 日志目录：`app/experiments/logs/three_machine/*`
2. 结束时可使用：

```bash
pkill -f app_coin_master || true
pkill -f app_acq_r2s_node || true
pkill -f app_udp_raw_replayer || true
```
