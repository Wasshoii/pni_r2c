# 四机严格版（A 主控 / B1 采集 / B2 采集 / C 发包）

## 四机角色

1. A 机（主控）
   - 运行 app_coin_master
   - 提供符合服务与采集控制服务

2. B1 机（采集-R2S 节点 1）
   - 运行 app_acq_r2s_node
   - 负责第一组采集通道（默认 4 路）

3. B2 机（采集-R2S 节点 2）
   - 运行 app_acq_r2s_node
   - 负责第二组采集通道（默认 4 路）

4. C 机（发包）
   - 运行 app_udp_raw_replayer
   - 同时向 B1/B2 两机发包

## 场景目录

1. 正确性测试
   - app/experiments/four_machine/correctness/

2. 极限性能测试
   - app/experiments/four_machine/extreme/

3. 稳定性测试
   - app/experiments/four_machine/stability/

每个场景均包含：

1. A_start_master.sh
2. B1_start_acq.sh
3. B2_start_acq.sh
4. C_start_sender.sh

## 模板与占位符

模板目录：app/config/four_machine/templates/

占位符：

1. __A_MASTER_IP__
2. __B1_ACQ_IP__
3. __B2_ACQ_IP__
4. __C_SENDER_IP__
5. __B_BIND_IP__（建议 0.0.0.0，用于 B1/B2 本地绑定）

运行时渲染目录：app/config/four_machine/runtime/

## 环境变量（四台机器均设置）

```bash
export A_MASTER_IP=<A机IP>
export B1_ACQ_IP=<B1机IP>
export B2_ACQ_IP=<B2机IP>
export C_SENDER_IP=<C机IP>
export B_BIND_IP=0.0.0.0
```

## 启动顺序

1. 在 A 机启动 A_start_master.sh
2. 在 B1 机启动 B1_start_acq.sh
3. 在 B2 机启动 B2_start_acq.sh
4. 在 C 机启动 C_start_sender.sh

## 默认端口规划

1. C -> B1：source 17100-17103，destination 18100-18103
2. C -> B2：source 17104-17107，destination 18104-18107

## 注意事项

1. 当前模板按 2 个采集节点、每节点 4 路通道设计。
2. 若扩展到每节点 24 路，请同步扩展：
   - coin_master_*.template.json 中 detectorSources
   - C_start_sender.sh 中发包端口范围
   - B1/B2 节点 r2s.channelIndices 与 coinClient.globalChannelOffset
3. 建议数据面网络与控制面网络分离，避免 SSH/gRPC 抢占带宽。
