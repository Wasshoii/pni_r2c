# 实验配置与脚本

## 单机脚本

1. 正确性测试
   - `app/experiments/run_correctness_local.sh`

2. 平衡吞吐测试
   - `app/experiments/run_balanced_local.sh`

3. 平衡吞吐稳定版（低内存）
   - `app/experiments/run_balanced_stable_local.sh`

4. 压力测试
   - `app/experiments/run_stress_local.sh`

日志默认输出到：`app/experiments/logs/`

## 建议测试顺序

1. 先跑正确性测试，确认数据链路和结果口径正确。
2. 再跑平衡吞吐，观察持续吞吐与资源占用。
3. 最后跑压力测试，定位瓶颈和极限点。

## 关键日志指标（建议重点关注）

1. 采集侧
   - `acqRxRateMpps`
   - `acqBandwidthMbps`
   - `acqTotalRxPackets`

2. 单事件处理侧
   - `recvRateMSingles`
   - `procRateMSingles`
   - `totalSinglesReceived`
   - `singles_processed`

3. 符合输出侧
   - `promptPairs` / `promptRateMPairs`
   - `delayPairs` / `delayRateMPairs`

4. 流式内存池
   - `memUsedMB`
   - `memMaxMB`
   - `memUsagePct`

## 常见判读

1. `totalSinglesReceived` 与 `singles_processed` 长期偏差过大
   - 可能是队列积压或处理跟不上。

2. `acqRxRateMpps` 持续高而 `recvRateMSingles` 低
   - 可能在采集->R2S 或发送链路存在瓶颈。

3. `memUsagePct` 长时间接近上限
   - 需要下调发包速率或增大内存池上限。
