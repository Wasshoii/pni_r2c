# 测试说明

测试分两层，不要混用通过标准。

1. **进程测试**：本机 `bin/test/*`，验证握手、数据面、PAUSE 等。不替代跨机 soak。
2. **多机实验**：`app/experiments/rdma_cluster/` + `app/config/rdma_cluster/` 剖面 JSON。用法与判据见 [RDMA多机实验.md](RDMA多机实验.md)。

Preset 总表见 [BUILD_AND_SETUP.md](../BUILD_AND_SETUP.md)。

## 进程测试：`test_synthetic_singles`（CPU，无 GPU）

多机 worker 用的 synthetic 生成器必须先在单机证明配对公式。覆盖：

- 奇数 chunk 拼接 ≡ `generateSyntheticSingles` 全量
- 两节点 prompt 同时、delay 仅 peer 加 `delayOffset_100fs`
- `eventIndex` 越过一个 period 后时间单调，prompt/delay 关系不变
- 一块跨越 prompt→delay 边界时仍配对

```bash
cd pni_r2c
cmake --preset linux-release-tests-pni
cmake --build --preset build-tests-pni -j --target test_synthetic_singles
./bin/test/test_synthetic_singles
# 或
ctest --test-dir build/tests/pni -R test_synthetic_singles --output-on-failure
```

`ctest -L pni -LE integration` 会带上这条。墙钟节流 / jitter / 本地 pause **不**在这里测。

真实 worker（`pairs` 与 `stream`）都按 `source.pushChunkSingles` 调用 `fillSyntheticChunk` 再 `sendSingles`；`stream` 只改停止条件（`runSeconds`）并允许无界 `eventIndex`。回放也是按段再按 chunk。

## 进程测试：`test_rdma_orchestration`

覆盖（InProcess，不要求 RNIC）：

- Register → OpenDataPlane → Start 顺序
- 双节点 synthetic complete / drain（按 worker 路径 `fillSyntheticChunk` 循环发送）
- 反压 drain
- `requireRoce` 无设备时拒绝 InProcess
- Heartbeat 遥测与 PAUSE 停发
- 单节点 `fillSyntheticChunk` 分块发送（prompt-only 时间戳对照全量生成）

同进程 RoCE 仅在有 verbs 设备时跑；否则该条 skip。

需要 GPU（符合引擎）。跨机极限、真实 RoCE 带宽 **不** 进这条测试。GPU 符合对数 **不能** 替代 `test_synthetic_singles` 的精确配对断言。

```bash
cd pni_r2c
cmake --preset linux-release-tests-pni
cmake --build --preset build-tests-pni -j
# 二进制：build/tests/pni/bin/test/test_rdma_orchestration 或 bin/test/test_rdma_orchestration
./bin/test/test_rdma_orchestration
```

ctest 里该目标标为 `integration`：

```bash
ctest --test-dir build/tests/pni -R test_rdma_orchestration --output-on-failure
```

其它常用目标：`test_streaming_coincidence`、`test_local_grpc_coin`（pni）；CUDA 侧见 BUILD_AND_SETUP。

## 多机实验怎么用

1. 每台 RoCE 机：`bash app/experiments/rdma_cluster/rdma_preflight.sh`
2. 编译 app：`linux-release-apps-basic`（coin）+ `linux-release-apps-cuda`（worker）
3. 改 JSON 里的 IP，选剖面（通路 / 正确性 / 回放 / soak / rate）
4. 先 `run_coin.sh <coin.json>`，再各 worker `run_worker.sh <worker.json>`
5. 看 coin `[CoinMaster nodes]` 的 `lag` / `buf` / `rdma`，以及 worker `[AcqR2SNode status]`

正确性：先 `sent≈received`，再比窗内 prompt/delay（可小于配置的 `promptPairs`）。  
极限：看 `recvRate`/`procRate`/`lag` 是否稳态，**不要**用对数当通过标准。

`source.mode=stream` 必须 `singlesPerSec>0` 且 `runSeconds>0`。采集模拟收发包本阶段未实现。
