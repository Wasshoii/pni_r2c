# 状态机、参数与调试指南

本文说明 coin（符合主控）与 worker（单事件节点 `app_acq_r2s_node`）的状态机、日志字段、可调参数，以及如何用周期状态行判断瓶颈。

跨机启动步骤见 [RDMA多机实验.md](RDMA多机实验.md)。时间对齐原理见 [STREAMING_COINCIDENCE.md](../STREAMING_COINCIDENCE.md)。JSON 字段全集见 [APP_CONFIG.md](../APP_CONFIG.md)。

## 状态机设计

系统里是 **两层** 状态，不要合成一个枚举。

- **Coin 编排**：集群级，用计数器表达（`connected` / `dataplaneOpen` / `startIssued` / `producersComplete`），没有独立 `ClusterState`。
- **Worker producer**：节点级，proto `SourceState`（日志里写成 `idle` / `run` / `pause` / `done`）。
- **PAUSE** 不是集群态，只覆盖单个 worker 的发送；RDMA 连接保持。

### Coin 编排（集群级）

握手：`RegisterNode` → `OpenDataPlane` → 仅当 `registered==N && dataplane_open==N` 后 `Start`。全部 `NotifyProducerComplete` 后 drain 对齐器。

```
WaitRegister → WaitDataplane → Ready → Running → Draining → Stopped
```

| 阶段 | 日志判据 | 含义 |
|------|----------|------|
| WaitRegister | `connected < N` | 未收齐 Register |
| WaitDataplane | `connected==N` 且 `dataplaneOpen < N` | 已注册，QP/数据面未齐 |
| Ready | 两边都满，`startIssued=false` | 可以 Start |
| Running | `startIssued=true` | 心跳可下发 PAUSE / RESUME / STOP |
| Draining | `producersComplete=true` 或 `complete=k/N` 已满 | 对齐器排空后写完 LMF |
| Stopped | 进程退出 | |

`Control.PAUSE/RESUME/STOP` 经下一次 Heartbeat（默认 1s）下发到 worker，不改变上表集群阶段。

### Worker 握手与 producer

`CoincidenceClient::start()` 固定顺序：

```
Register → OpenDataPlane → WaitForStart → run（sender + heartbeat 线程）
```

任一步失败则 `start()` 返回 false，进程退出。握手步骤会打 stdout：`handshake=reg|dp|wait|run`。

Producer `SourceState`：

| 日志 | proto | 含义 |
|------|-------|------|
| `idle` | `SOURCE_STATE_IDLE` | 已连接但尚未发送；WaitForStart 期间心跳线程尚未起来，coin 侧可能仍是默认值 |
| `run` | `SOURCE_STATE_RUNNING` | `sendSingles` 可入队 |
| `pause` | `SOURCE_STATE_PAUSED` | 阻塞入队，RDMA 保持 |
| `done` | `SOURCE_STATE_COMPLETE` | 已 `NotifyProducerComplete` |
| `err` | `SOURCE_STATE_ERROR` | 枚举存在，**当前代码不会设置** |

`synthetic` / `lsingle_replay`：握手成功后一次性推数，发完 complete 再退出。`acquisition` 本阶段仍是 stub。

### 仍报 `run` 的阻塞子态

这些 **不是** `SourceState`，要从缓冲/credit 判断：

1. Worker `pend` 顶满 `maxPendingChunks`：CPU 发送队列满，`sendSingles` 等待。
2. `rdma` credit 为 0：TX 槽等对端消费。
3. Coin `buf` 顶满 `maxChunksPerNode`，或 `memUsagePct` 接近 100%：aligner ring / 内存池反压，最终表现为 worker 的 pending 或 credit 堆积。

## 参数含义

对照配置与日志。worker 配在 `cluster` / `dataplane` / `coinClient` / `source`；coin 配在 `cluster` / `dataplane` / `coincidence` / `runtime`（旧 `coinMaster` / `aligner` 段仍可解析）。

### Worker 可调

| 参数 | 作用 | 日志对照 |
|------|------|----------|
| `maxPendingChunks` | 本机待发送 chunk 上限，满则阻塞 `sendSingles` | `pend=used/cap` |
| `dataplane.txSlotCount` | 本地 TX 槽数（0 用默认 8） | `rdma=credit/slots` |
| `heartbeatIntervalMs` | 心跳间隔，默认 1000；控制命令与遥测都走心跳 | coin 上 `age`、`rtt` |
| `source.pushChunkSingles` / `coinClient.batchSize` | 每块 singles 数 | 影响 chunk 粒度与 `pend` 增长速度 |
| `source.singlesPerSec` | 合成/回放墙钟节流；0 表示尽快发（仅 `pairs`） | worker `sent` |
| `source.mode` | `pairs` 有限对数；`stream` 按时长生成 | soak/rate 剖面 |

### Coin 可调

| 参数 | 作用 | 日志对照 |
|------|------|----------|
| `aligner.maxChunksPerNode` | 每节点 aligner ring 容量（chunk） | `buf=used/cap` |
| `aligner.maxTotalMemoryBytes` | 共享内存池上限 | `memUsedMB` / `memUsagePct` |
| `aligner.processingIntervalMs` | 对齐循环间隔 | `avgProcMs`、`procRate` vs `recvRate` |
| `coinMaster.statusPrintIntervalMs` | coin 状态打印间隔，默认 1000 | 周期行频率 |
| 心跳超时 | 服务端默认 3000 ms（`CoinGrpcNode.heartbeatTimeoutMs`，当前 JSON 未暴露） | `live=n` 且 `age` 超过该值 |

### 日志字段

Coin 约每秒三行：`[CoinMaster status]`、`[CoinMaster Stream_coin]`、`[CoinMaster nodes]`。

Worker 合成/回放路径：`[CoincidenceClient] handshake=...`，发送期间 `[AcqR2SNode status]`。Acq+R2S 路径另有 `[AcqR2SNode/Perf]`（本阶段采集未接真源）。

| 字段 | 出现位置 | 含义 |
|------|----------|------|
| `connected=k/N` | coin status | 已 Register 数 / 期望节点数 |
| `dataplaneOpen` | coin status | 已 OpenDataPlane 数 |
| `startIssued` | coin status | 是否已发 Start |
| `complete=k/N` | coin status | 已 complete 的 producer 数 |
| `windows` | coin status | 对齐窗口处理次数（`chunksProcessed`） |
| `avgProcMs` | coin Stream_coin | 对齐循环平均处理时间 |
| `recvRate` / `procRate` | coin Stream_coin | 收到 / 处理 singles 速率（M/s） |
| `memUsagePct` | coin Stream_coin | 内存池占用 |
| `state` | 每节点 / worker | `idle` `run` `pause` `done` |
| `live` `age` `rtt` | 每节点 | 心跳是否超时、距上次心跳、RTT |
| `sent` | 每节点 k/s；worker 累计 | worker 声称已入队发送的 singles |
| `pend` | 每节点 / worker | 发送队列 used/cap |
| `rdma` | 每节点 / worker | credit 剩余 / slot 总数 |
| `buf` | 每节点 | aligner ring used / `maxChunksPerNode` |
| `lag` | 每节点 | `singles_sent_heartbeat - singles_received`（管道积压） |
| `lease` | 每节点（仅 `r2s_lease_cap>0`） | R2S lease used/cap |
| `r2s` / `acq` | 每节点 | 预留速率；合成路径为 0 |

`GetStatus(include_node_stats=true)` 与 stdout 使用同一套字段。

## 调试指南

先看 coin 的 `status` 判断编排阶段，再看 `nodes` 表定位哪台 worker，最后用 worker 本机行对照。不要只改一个参数。

```
pend满 + credit>0     → 加大 maxPendingChunks，或 sender 线程慢
credit=0 + buf未满    → 加大 txSlotCount，或 recv CQ/消费慢
buf顶满 + mem高       → 先看 GPU / processingIntervalMs / 内存池，不要只加大 maxChunksPerNode
一节点 buf空、其它满  → 该节点源慢或断流，watermark 被拖住
recvRate>>procRate    → 符合计算/写盘瓶颈，不是 RDMA
sent>>recv 持续增大   → lag 升高：数据面入 aligner 卡住（push 阻塞或 recv 未回调）
live=n 且 age>timeout → 心跳丢失，先查网络/进程，再看速率
state=pause 且 sent≈0 → 人为暂停，不是瓶颈
```

调参顺序建议：确认 `live=y` 且 `startIssued=true` → 看 `lag` / `buf` / `rdma` / `pend` 用上面口诀 → 最后才动时间窗或 GPU 相关间隔。

本阶段不统计 `waitPendingMs` / CQ 完成速率 / GPU 队列深度；一阶定位以上面字段为准。
