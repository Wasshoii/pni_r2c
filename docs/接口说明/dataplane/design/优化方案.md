# 数据面优化方案（下周上机）

给有环境时改实现用。背景与「为什么现在这样」见 [数据面通路现状与评价.md](数据面通路现状与评价.md)。**本期不改代码语义上的有序发送模型**（仍是 `next()` + 单消费线程填 TX）。

单位仍按 **Gibit/s**。未上机前不要把默认 TX 从 2 一次改到几十。

---

## 1. 目标与非目标

**要做：** 去掉热路径上不必要的等待（切 GPU 重建 stream、pageable D2H、CQ 噪音），并在实测后再评估 TX 2→4。

**不做：**

| 项 | 原因 |
|----|------|
| GPUDirect / `ibv_reg_mr(GPU)` / `nvidia_peermem` | 另档；见 [GPUDirectRDMA.md](../rdma/GPUDirectRDMA.md) |
| 把 `SlotChunkView` 指针送进 `TimeAligner` | 槽指针只在 ingest 返回前有效；credit 一涨，下一发 WRITE 会覆盖该槽。对齐器按到达序持有块、半块用 `consumed` 下标、还要 steal/reinsert。指针留在环上会在水位线尚未切走时被覆盖；若拖到对齐器消费完再放 credit，credit 窗和 `maxChunksPerNode` 绑死，对齐器等水位、发送等 credit，可能互等。正式 ADR 见 [数据面通路现状与评价.md](数据面通路现状与评价.md) §3.5 |
| 把跨槽 PARTIAL 当成独立 chunk `push` | 同一 `chunkId` 的多槽必须先在 `m_partialByNode` 拼完。拆开 push 会改 `m_expectedChunkId` 语义 |
| 单槽那一次 `memcpy` 进 `std::vector` | **保留**。这是离开 RDMA 环、让 credit 能涨的那一次，水位线逻辑依赖这份独立存储 |
| 加大 `slotBytes` / 把 RX 开到数百槽当「加速」 | 不加线速，只加尾延迟和更晚的反压，见现状文档 §1.6 |

---

## 2. 优先级与改法

### P0-1 每 GPU 常驻 D2H stream（高）

**现状：** [`CoincidenceClient::ensureTxD2hStream`](../../../../src/grpcService/CoincidenceClient.cpp) 在 `m_txD2hDevice != device` 时调用 `destroyTxD2hResources()`，拆掉唯一的 `cudaStreamNonBlocking` 和全部 event。多卡 `next()` 相邻两段常换 GPU，等于每段重建 stream。

**改：** 按 device 缓存 `{stream, events[]}`（例如 `unordered_map<int, TxD2hResources>`）。`fillRoceTxAndCommit` 仍只在 `consumerLoop` 里按 `next()` 序拷，**不**变成每卡一条发送线程。`stop()` 时销毁所有 device 上的资源。

**文件：** [CoincidenceClient.hpp](../../../../include/grpcService/CoincidenceClient.hpp)、[CoincidenceClient.cpp](../../../../src/grpcService/CoincidenceClient.cpp)。

**验收：** 连续两段来自 GPU0/GPU1 时，日志或计数显示不再 `cudaStreamCreate`；`seq` 仍单调；单测 `test_rdma_dataplane_loopback` / 现有 R2S 回调路径不回退。

### P0-2 `cudaHostRegister` 失败则 RoCE 开不起来（高）

**现状：** `openRdmaDataPlane` 注册失败只 WARNING，热路径可能对 pageable TX 做 `cudaMemcpyAsync`，桌面审查里这是最可能把「理论实时」打穿的点。

**改：** `rdmaSender->kind() == RdmaRoceV2` 且（`requireRoce` 或生产默认）注册失败 → `openRdmaDataPlane` 返回 false，不进入 `WaitForStart`。InProcess 不要求 register。

**文件：** 同上 `CoincidenceClient.cpp`（`openRdmaDataPlane` 里 `tryCudaHostRegister` 之后）。

**验收：** 人为让 register 失败时节点起不来并打明确错误；成功时日志仍有 `txCudaRegistered=1` 一类信息（可新加一行 INFO）。

### P1-1 TX 槽 2→4：可配，上机 A/B，不要一次跳几十（中）

**现状：** `txSlotCount` JSON 已有；`setupTxArena` 至少 2。CUDA 管线深写死 `min(4, txSlotCount)`，默认因此是 2。

**改：**

- 把 `depth = min(4, txSlotCount)` 的 4 改成「等于 `txSlotCount`」或单独配置项，避免槽开到 4 了管线仍被 2 卡住（默认 2 时 `min(4,2)=2`，开到 4 时才会吃到 4）。
- 默认值先保持 2，或仅在实验配置里设 4。上机对比 2 vs 4 的 D2H 等待、send CQ 等待、`waitForCredit` 时间。
- **不要**把默认改成 16/64。credit=0 时 `commit` 仍堵；多出来的槽只是囤已拷数据（现状 §1.6）。

**文件：** `CoincidenceClient.cpp`（`fillRoceTxAndCommit`）、节点 JSON / `CoincidenceClientConfig::txSlotCount` 注释。

**验收：** `txSlotCount=4` 时同时在飞 D2H 可达 4；吞吐若无提升，默认改回 2 并在配置注释里写明。

### P1-2 credit WRITE 降噪（中）

**现状：** [`RdmaNodeRecvSession::postCreditWrite`](../../../../src/dataplane/rdma/RdmaRecvServer.cpp) 每次 `signaled=true`，和 payload IMM 挤同一 CQ。credit 语义（8 字节 `consumerSeq` WRITE 到 `creditMirror`）不要改。

**改（二选一，先做简单的）：**

- 每 N 次 credit WRITE 才 `signaled`（例如 N=8），其余 unsignaled；或
- 保持每次 WRITE，但发送端 `waitForCredit` 里更积极 `recycleTxCompletionsLocked`（这项帮的是 TX 回收，对 coin CQ 噪音无帮助）。

优先改 coin 侧每 N 次 signaled。N 不可太大，以免 `maxSendWr` 被 unsignaled WR 填满（`RdmaConnection::create` 接收端 `maxSendWr=256`）。建议 N=8，并在 outstanding 接近上限时强制一次 signaled。

**验收：** `consumerSeq` 仍单调追上；worker 不再出现「credit 卡住但 coin 已 ingest」；CQ poll 次数下降可作次要观察。

### P2-1 poller 少复制 session 列表（低）

**现状：** `RdmaRecvServer::pollLoop` 每次加锁 `push_back` 全部 `shared_ptr`。有流量时连续 `pollOnce(16)` 也会每圈复制。

**改：** 列表只在 `ensureSession` / `stop` 时 dirty；热路径用本地缓存的 vector。空闲 `sleep 10µs` 可保留。

**文件：** [RdmaRecvServer.cpp](../../../../src/dataplane/rdma/RdmaRecvServer.cpp) / [RdmaRecvServer.hpp](../../../../include/dataplane/rdma/RdmaRecvServer.hpp)。

**验收：** 多 node `OpenDataPlane` 之后 poller 仍能 ingest 新 session；`stop` 后不再碰已 close 的 session。

### P2-2 remap 放到 D2H 之前（低，可选）

仅当生产开了 `remapLocalToGlobalChannels`。否则 D2H 后 CPU 扫最多 262140 条。可在该卡 `d_singles` 上起一个小 kernel，或确认 R2S 侧已能出全局 channel 则关掉 client remap。

**不作为第一周必做。**

## 3. 上机顺序

每步看 **worker 是否停在 `waitForCredit`**。若是，问题在 coin 对齐器 / ingest，加大 TX、常驻 stream、credit signaled **都无效**，应去看 `NodeRingBuffer` 占用和水位线，而不是继续拧数据面旋钮。

1. **基线：** 确认日志里 TX `cudaHostRegister` 成功。临时打（或已有心跳）D2H 同步等待、send CQ 空转、`creditRemaining`、`txSlotsBusy`。跑一段接近目标速率的负载。
2. **P0-2：** register 失败即启动失败。避免后面所有数字都是 pageable D2H。
3. **P0-1：** 常驻 per-GPU stream。对比切卡时的 `cudaStreamCreate` 次数和 D2H 间隔。
4. **P1-1：** 同一二进制 A/B `txSlotCount=2` 与 `=4`（管线深跟槽走）。看 D2H/CQ 等待是否下降；`waitForCredit` 若反而变长，说明在囤槽，改回 2。
5. **P1-2：** 再动 credit signaled。单独对比，不要和第 4 步同时改。
6. **P2：** 有余力再做 poller 列表缓存。
