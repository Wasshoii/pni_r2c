# 性能测试

吞吐、时延、soak 等，不要和正确性测试混用通过标准。源码目录：`tests/performance/`。产物仍在 `bin/test/`。CTest 标签：`performance`，通常再加 `manual`。默认 CI（`-LE "integration|manual"`）不跑。

本目录测的是生产接口上的墙钟（含类 RDMA 填 TX），不是 Pref 那种扩包/只跑核、不下 singles 的极限 R2C。

## test_r2s_50100_single_ring

50100 单环（NECR1/930）R2S 吞吐。

- **模块**：`createBDM50100Config` + `R2SStreamProcessor::processSegment`（多 GPU，串扰开，外部 sort 关）。热路径 span 是 device；`onSinglesSpanReady` 按 4 MiB 槽、**2 槽** ping-pong `cudaMemcpyAsync` 进预分配缓冲（模拟 `fillRoceTxAndCommit` 的 copy stream）。不写 `.lsingle`。
- **用法**：preset `linux-release-tests-cuda`。  
  `./bin/test/test_r2s_50100_single_ring [--raw-dir DIR] [--cali-dir DIR] [--max-files N] [--max-segments N] [--pipeline-depth N] [--pinned-preload]`  
  默认 raw：`/media/lenovo/1TB/50100data/pni_res/NECR1`；校正：`pni_res/caliFile`；`--pipeline-depth` 默认 2。`--pinned-preload` 只作对照。标签 `cuda performance manual`，超时 7200s。
- **依赖**：CUDA、NECR1 `pniRaw-*.bin`、`bdm_*.bin`。缺数据或无 GPU 打印 `SKIP:` 并以 0 退出。
- **指标**：合计墙钟（含填槽）、TX-fill 墙钟、TX-fill payload GB/s、R2S-only、合计/R2S-only Gib/s。无 pass/fail 阈值。单卡 Combined 应回到 **≥25 Gib/s**（改前同步切槽 D2H 约 26）；TX-fill payload 应明显高于同步 D2H 的 ~2 GB/s。R2S-only 是扣掉回调拷贝后的 GPU 时间，不含整段 host D2H。
- **不是**：`Pref_50100r2c` 的扩包 R2C，也不是空 callback / 跳过 D2H。

## test_coin_9120_aligner

9120 双节点符合吞吐（生产 `StreamingTimeAligner`）。

- **模块**：`createBDM50100_9120AlignerConfig` + `StreamingTimeAligner`（每节点 steal 线程整块 swap 进有界 deque + 协调线程切段归并 + 多 GPU 抽取/收回流水线 + 按序异步写盘，事件驱动水位线 + carry）。预读 `pni_singles_node0/1` 的 `.lsingle` 后两线程 burst `push`，环深用工厂值（默认 1000，不扩到能装下整份数据）。水位线仍按双节点 `min(maxEventTime)-margin` 计算；处理循环由 push 唤醒，按攒批软下界 / 缓冲高水位 / 延迟兜底触发，每次抽出的段受 `maxSegmentSingles`（默认 262144，含 carry，约一个 4 MiB RDMA 槽）与 `minSegmentOverlapFactor` 硬下界约束。Steal 不按水位切前缀；条数预算只在协调线程的归并前缀上切，不按节点均分。stop 后先 join steal（环抽进 deque），再抽空 deque 并 flush 安全边际残留。默认 `push-chunk` 为一个 4 MiB RDMA 槽能装的 singles 数。`processingIntervalMs=0`。**默认写 LMF** 到 `/tmp/r2c_coin_9120_perf`（约 785 MiB prompt+delay；这份复制数据 prompt≈输入 singles）。`coinPipelineDepth` 默认 0（按 GPU 数推导）。`--extract-only` 只抽不核（隐含 `--no-write-lmf`），用来在单卡上验收抽取能否喂饱多卡；`--steal-only` 只测锁/swap 墙。
- **用法**：preset `linux-release-tests-cuda`。  
  `./bin/test/test_coin_9120_aligner [--data-root DIR] [--max-files N] [--max-singles N] [--push-chunk N] [--max-chunks N] [--max-segment N] [--kernel-batch N] [--min-segment N] [--min-overlap-factor N] [--high-water R] [--max-latency MS] [--burst-skew N] [--pipeline-depth N] [--write-lmf] [--no-write-lmf] [--extract-only] [--merge-pinned] [--steal-only]`  
  `--kernel-batch` 是 `--max-segment` 的兼容别名。`--write-lmf` 是默认行为的兼容别名；`--no-write-lmf` 关闭写盘。`--extract-only` / `--steal-only` 都隐含 `--no-write-lmf`。`--merge-pinned` 隐含 `--extract-only`，归并写入 pinned 以模拟生产槽。默认 root：`/media/lenovo/1TB/50100data/test_9120`。`--burst-skew N` 让 node1 落后 node0 N 个 chunk，用于走压力触发与背压路径。标签 `cuda performance manual`，超时 7200s。
- **依赖**：CUDA、双节点 `.lsingle`。缺数据或无 GPU 打印 `SKIP:` 并以 0 退出。
- **指标**：合计墙钟、Coin-kernel / Align-extract / Steal / Merge / Watermark / Slot wait / Drain wait / Write queue wait / Sink、水位线抽出次数、核批次数、触发来源（watermark / pressure / deadline）、`heldByMinDuration`、`watermarkStallEvents`、`oversizedSegments`、carry 重算开销比（`carrySinglesTotal / processed`）、input Gib/s、singles/s、Extract singles/s、相对「92 M singles/s/GPU」的倍数、pairs/s。无 pass/fail 阈值。Align-extract 只含协调线程切点/归并/carry；Steal 是 N 条 steal 线程的 swap/切前缀累计；Merge 是归并。等输入槽是 Slot wait；水位线与触发判定是 Watermark。Sink 是写盘线程累计；Drain wait 是收回线程等 GPU；Write queue wait 是写队列满时的背压。 Combined 含写盘后用这三项区分核和盘。`--extract-only` 时 Combined 应贴近 Align-extract，Slot wait / Coin-kernel / Drain wait 近 0；抽取目标 ≥ **400 M singles/s**（约 5 卡 × 92 M），实时入流 **60 Gib/s**（503 M singles/s）要求 Combined ≥ 60 Gib/s。`--merge-pinned` 测 pinned 写出。`--no-write-lmf` 且有核时 Combined 仍可被核钉住。
- **不是**：`test_coin_streaming_aligner` Test7 的限速 soak，也不是只调 `S2CCompute` / 扩包。
